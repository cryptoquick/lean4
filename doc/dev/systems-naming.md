# Systems product naming

**Status:** normative for new work (2026-07-19).  
**Plan:** `.agents/plans/plan-systems-naming-cleanup.md`  
**Related:** [systems-lean.md](systems-lean.md), [RESIDUAL.md](../../RESIDUAL.md)

This document governs how freestanding **PRODUCT** modules under `src/Systems/` are named and what may be added to `script/systems-product-stdlib-modules.txt`.

---

## Principles

1. **Name the thing that exists.** The filename and namespace should match the algorithm, layout, or responsibility a caller would search for (`TomlConfig`, `BinaryHeap`, `OrderedU32Set`, `Proc`).
2. **One module per distinct behavior.** If two translation units differ only by a constant, an accessor name, or a thesaurus synonym, they are **not** two product modules.
3. **Honesty lives in the module header**, not in a universal suffix. State what the module is, what it is **not**, and the freestanding contract in the docstring.
4. **Standards numbers only for real subsets.** Names like `G711`, `Http`, or `Tls` are allowed only when tests describe multi-field or stateful behavior worth the name. Matching a 6-byte ASCII tag is not a codec. A 4-byte “sync/rate/ctrl/spare” toy is not an ITU V-series modem.
5. **Thoughtful changes only — no bulk rename.** See [Hard rule](#hard-rule-no-bulk-rename) below. This is persistent.
6. **PRODUCT is not a trophy case.** Residual waves must not add modules to inflate `FS_READY`. A falling count after deleting nonsense is a **win**.

---

## Hard rule: no bulk rename

**Do not** bulk find-and-replace module names, export prefixes, or twin-peer docstring lists.

Forbidden examples:

- Tree-wide `sed -i` / codemod “rename all `*Lite`”
- Mass `git mv` scripts driven only by a regex
- Generating N modules from a template with fashion-word or standard-number labels

**Do:**

- Open the module, read what it implements
- Classify: keep / intentional rename / delete
- Update **that** module’s edges deliberately (manifest, corpus, allowlist, lakefile roots, Extract, smokes)
- Prefer small PRs with a one-sentence rationale that would make sense to a future reader

Automation is allowed for **read-only inventory** and for **fail-closed gates** after humans edit manifests — never for choosing names.

If a change cannot be justified in one plain sentence, it does not land.

## Legacy `Lite` suffix

Historically, `*Lite` meant “shaped freestanding port, not full Init/X parity.” That marker failed:

- Core modules already use plain names (`Scalars`, `Sys`, `Bytes`, `Proc`, `Status`, …)
- C exports often already drop `lite` (`lean_fs_tomlcfg_*`, `lean_fs_heap_*`)
- `Lite` does not distinguish a real algorithm from a clone farm

**Policy going forward:**

- **New PRODUCT modules must not use the `Lite` suffix.**
- After Phase D21, product residual `*Lite` count is **0** (`src/Systems/*Lite*.lean` empty; manifest has no `*Lite` basenames). The Phase E gate fail-closes reintroduction (empty Lite allowlist = zero exceptions).
- Shipping **new** `*Lite` files is not allowed. Intentional renames of any future accidental `*Lite` land one module/family at a time under the hard rule above — not in a big-bang rename.

## Forbidden PRODUCT patterns

Do **not** add to PRODUCT_STDLIB:

| Pattern | Why |
|---------|-----|
| New `*Lite.lean` | Legacy honesty tag; use a plain name |
| Thesaurus “heap” names (Yarn, Cable, Weave, Plait, Braid, Twine, Rope, Skein, …) as product | Same ordered-set body with a fashion label |
| `V[0-9]+` modules whose body is only sync/rate/ctrl/spare | Fake modem headers; not protocol implementations |
| `G7*Nb` / pure `*Nb` modules whose body is only ASCII magic match | Fake annex codecs |
| Residual “Track L free trio” / “+3 FS_READY names” packing | Wave filler; frozen |

Deleting such modules (after per-module audit) is preferred over “collapsing” them into generic `SyncHeader` / `MagicTag` PRODUCT stand-ins. Nonsense shapes should leave the product surface, not get a cleaner alias.

**Enforced by gate (Phase E):** `script/systems-product-stdlib-check.sh` fail-closes manifest basenames matching `*Lite`, pure `V[0-9]+`, pure `G7*Nb`, fashion words / `*Heap` fashion, and `HeapSet`. Token: `PRODUCT_NAMING_GATE_OK=1` on success. Negatives: `script/systems-product-stdlib-check-negatives.sh`.

## What good looks like

| Role | Example direction |
|------|-------------------|
| Core freestanding | `Proc`, `Bytes`, `Scalars` (already) |
| Fail-closed config subset | `TomlConfig` (shipped; fail-closed lakefile.toml subset) |
| Real collection | `BinaryHeap`, `OrderedU32Set`, `Map`, … after audit |
| Real codec/parser | Only if the implementation and tests justify the standard or format name |

Module docstring checklist:

- What algorithm or layout is implemented
- What it is **not** (full ITU stack, full TOML 1.0, managed GC collection, …)
- Freestanding / residual-clean contract in one line
- **No** fifty-name “distinct from …” twin-paste lists used to paper over clones

## Residual-wave recipe (after freeze)

| In scope | Out of scope |
|----------|--------------|
| H5 honesty-only (never forge `GC_FREE_ELABORATOR=1`) | Track L +3 name packing |
| TomlConfig moreN — real Lake JSON/TOML object keys only | Thesaurus / V## / magic-only product adds |

| Naming cleanup phases (policy → audit/delete → intentional rename) | Bulk de-Lite |
| A new module only with a **written purpose** in the PR | “Next free Heap/V/G name” |

`PRODUCT_FS_NEXT` remains a curated backlog string (e.g. `H5_host,TomlConfig_moreN,Slake_parity_more`). It does **not** imply a Track L trio.

## `FS_READY` honesty

`FS_READY` counts intentional residual-clean product modules in the manifest.

- Inflating the count with clones was a process failure; cleanup will **lower** the count.
- Gates must stay green on residual/axiom/product membership — not on “count ≥ previous wave.”
- Celebrate honest surface area, not trophy cardinality.

---

## Inventory method (read-only; before deletes)

For each cleanup PR family:

1. List candidate paths (human-curated family list — not a blind glob drive-by delete).
2. For each path, **read** the module and one peer; record a one-line verdict:
   - `DELETE_NONSENSE` — rename clone, 4-byte header toy, 6-byte magic toy, …
   - `KEEP_UNIQUE` — real algorithm/layout; schedule intentional rename if needed
   - `KEEP_SURVIVOR` — last copy of a real shape until renamed
3. Delete or rename only with that verdict; update harness edges in the **same** PR.
4. Update the **effort ledger** (below).
